## Built "Finora" — personal finance app (Laravel 13 + Tailwind 4 + Chart.js)

Stack: Blade + Tailwind 4 (Vite 8), Chart.js 4 via npm (`window.Chart`), MySQL `finance-app` on port 3307. UI is **English**, currency formatted Indonesian-style (`Rp5,400,000`).

Key decisions from the user: multi-user auth (custom, no Breeze), Google Sheets **direct sync** (service account JWT over REST, no `google/apiclient` dependency), Telegram token configured through the Settings page.

Data model (`database/migrations/2026_11_23_*`): `categories` (2-level: group + leaf, `type` income/expense, `parent_id`), `transactions`, `budgets` (period `YYYY-MM`, nullable category = overall), `savings_goals`, `holdings`, `integrations` (provider + JSON config, unique per user/provider).

Important architecture notes:
- `App\Services\ReportService` is the single source of truth for monthly summary, 6-month growth series, hierarchical report, budget-vs-actual (groups spending via `COALESCE(parent_id, category_id)`), portfolio and savings aggregates, and `spreadsheetRows()` used by both CSV export and Sheets sync.
- `App\Services\CategoryTemplate::seedFor($user)` seeds the exact tree from the user's spreadsheet (Gaji/Magang, Side Jobs/ShopeeFood, Investasi/Dividen, Pokok/…, Transportation/…, Shopping Bulanan/14 leaves, Shopping Sekunder/Self Reward). Called on registration; 34 categories per user.
- `App\Services\TelegramBot` parses free text (`makan 25000`, `kopi 15rb`, `jajan 2jt`, `income shopee 180000`) and resolves categories; category type overrides direction when no explicit `income/expense` prefix. Commands: `/saldo`, `/budget`, `/laporan`.
- `App\Services\GoogleSheetsService` signs an RS256 JWT with the service account key and calls the Sheets REST API directly.
- `App\Support\Money` handles Rupiah format/compact/parse (dots as thousands, `rb`/`k`/`jt` suffixes handled in TelegramBot).
- CSRF exemption for `telegram/webhook/*` lives in `bootstrap/app.php` — required or Telegram gets 419.
- Blade directives `@money` / `@compact` registered in `AppServiceProvider`.
- Views use `<x-app-layout>` / `<x-guest-layout>` (anonymous components in `resources/views/components/`), plus `<x-icon name="…">`, `<x-period-picker>`.

Demo account: `demo@finance.app` / `password`. Seeded month reproduces the user's spreadsheet exactly (Pokok 1,997,000 / Transportation 166,667 / Shopping Bulanan 355,000 / expense total 2,668,667, income 5,400,000).

Gotcha learned: MySQL `utf8mb4_unicode_ci` is case-insensitive, so a cleanup `whereIn('description', ['bensin'])` also deleted the seeded `Bensin` rows. Prefer `migrate:fresh --seed` for demo resets.

## Bug: flex column squashed page content (found on Budgeting)

Adding `flex flex-1 flex-col` to `<main>` made every page child a flex item, and flex items shrink by default. On pages taller than the viewport (Budgeting, Reports) the stat strip collapsed to ~15px and table headers were clipped.

## Sortable columns, modal confirmations, post-save choice

**Sorting (Income/Expense)**
- Whitelist in `TransactionController@index`: date, group, category, description, source, amount → `$sort` / `$dir` query params, default `date desc`.
- Sorting by `category` / `group` needs the categories table, so the query gets `leftJoin('categories as categories', ...)` + `leftJoin('categories as parents', ...)` + `select('transactions.*')`.
- Gotcha: `scopeForUser` / `scopeOfType` used bare `user_id` / `type`, which became ambiguous once categories were joined (SQLSTATE 1052). Both scopes now use `$query->qualifyColumn(...)`.
- Second gotcha: the base query still had `orderByDesc('date')->orderByDesc('id')`, so a new `orderBy` only acted as a tiebreaker and category sorting appeared broken. Removed them — sorting is applied once, at the end.
- Headers are `<a data-sort-link>` with a `data-sort-indicator` span; AJAX keeps `sortState` and repaints the arrows from the JSON response.

**Confirmations**
- `<x-modal id="confirm-modal">` lives in `app-layout`, driven by `window.askConfirm(form, message, {label, danger})`. It calls `form.submit()` (bypassing the submit handler) so there is no recursion.
- All six `onsubmit="return confirm(...)"` call sites were replaced. Edit submits (transaction + category modals) also route through `askConfirm` when `_method=PUT`.
- `.btn-destructive` added to `app.css` for the red confirm action.

**Post-save choice**
- `store()` redirects with `?created=1`; the index opens a "Saved" modal offering "Add another" (reopens the add modal) or "Back to list". The param is stripped with `history.replaceState` so a refresh does not reopen it.

**Testing note**: to screenshot pages containing live forms, inject a script that calls `preventDefault()` on every form submit before loading the snapshot. This prevented the data drift seen earlier — November expense stayed at 2,668,667 across all screenshot runs.

## Debts feature (Utang) + net worth integration

New `debts` + `debt_payments` tables (migration `2026_11_25_000001`), models `Debt` / `DebtPayment`, `DebtController`, routes under `/debts` (index/store/update/pay/destroy), view `debts/index.blade.php`, sidebar item **Debts** between Savings and Portfolio (icon `debt`).

- `type` is `debt` (you owe) or `receivable` (owed to you). `remaining_amount` is the source of truth; `principal_amount` drives the progress bar.
- `pay` never applies more than what is left (`min(amount, remaining)`), records the **applied** amount in `debt_payments`, and flips `is_settled` at zero.
- `Debt::summaryFor($userId)` returns payable / receivable / net / monthly / settled — reused by portfolio and savings.
- **Portfolio**: 5th KPI cell "Net worth" = market value − net debt, with a caption "assets less/plus … debt/receivable". Grid is now `lg:grid-cols-5`.
